有些事刚开始做，手感就是很差。想法说不清，代码反复报错，写出来的句子也怎么看都别扭。

这时候很容易把不舒服当成提示，觉得自己是不是走错了，或者根本做不来。可它也可能只是说明，你已经碰到一块还不熟的地方。光靠想，通常分不清是哪一种。

## 不舒服不一定是在劝你停下

我不太相信一个简单的判断规则，比如「做得顺就是对，做得难受就是错」。熟悉的事当然容易顺手；新的事也确实会让人卡住。但卡住本身不能证明方向对，也不能证明方向错。

能做的，是先把这股不适放在旁边，别急着让它替你做决定。先按眼前的目标判断要不要继续。

## 给想法一个能落地的抓手

光是忍着不舒服，容易变成另一个循环，脑子里一直盘算，手上什么也没发生。

我更愿意把工具当作一块脚手架。它不替我决定要做什么，但可以帮我更快做出一个能看的版本。草图、几行代码、一段文字都行。东西一旦摆到眼前，讨论就不再只围着想象打转。

```typescript
// 下面只是把想法到反馈的回路写成伪代码，不是可直接运行的实现
interface CreativeLoop<TInput, TOutput> {
  intuition: TInput;
  scaffold: (raw: TInput) => Promise<TOutput>;
  observeFriction: (result: TOutput) => number;
  crystallize: (feedback: number) => void;
}

// 先做一步，再看结果
while (creativeFriction > THRESHOLD) {
  await actSmallestStep();
  measureSignal();
}
```

## 先把眼前的问题说清楚

想法留在脑子里时，什么都还可能；写下来或做成原型之后，才会发现自己到底卡在哪。

## 把下一步缩小一点

任务越大，越容易盯着终点发愁。我的办法不是给自己打气，而是把眼前那一步再缩小一点。

1. 想搭整套框架时，先写一行类型定义。
2. 想把网站全做完时，先画一张草图。
3. 想写一篇大文章时，先写一段能读懂的话。

做完这一步，不代表不确定感就消失了。只是你手里多了一点真实反馈，下一步也能跟着它调整。

不舒服可以先在旁边待着。现在，去做那件真正重要的事，哪怕只动手十分钟。
