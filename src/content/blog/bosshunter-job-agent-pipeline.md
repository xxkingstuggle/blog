在同时投递**产品经理 / 产品助理**与**AI 应用 / Agent 开发**两类关联但侧重点不同的岗位时，手工在招聘平台逐条筛选 JD、判断技术栈或业务匹配度、选择对应版本的招呼语与简历，存在大量重复机械的认知消耗。

但如果只写一个粗暴的爬虫脚本无脑群发，不仅转化率极低，还会在几分钟内触发招聘平台的频率风控与安全验证码。为此，我设计并开源了 [**BossHunter**](https://github.com/xxkingstuggle/BossHunter)——一个以**“多画像精准评分、本地幂等账本、拟人节流与风控即停”**为核心原则的求职辅助 Agent。

## 一、多画像 YAML 规则引擎：拒绝盲目海投

`BossHunter` 不对搜索结果做无差别打招呼，而是先通过 `config/jobs.yaml` 定义结构化的**岗位画像（Role Profiles）**与双向过滤规则：

1. **正向能力与场景加权**：针对“AI 应用 / Agent 工程”画像，匹配 `Agent`、`MCP`、`Skill`、`多模型网关`、`RAG`、`TypeScript/Python/Swift` 等关键词并赋予权重；针对“AI 产品经理 / 产品助理”画像，匹配 `B2B2C`、`需求拆解`、`Figma 原型`、`研发协同`、`教育/SaaS` 等关键词。
2. **硬性红线一票否决（Hard Exclusions）**：自动过滤职责不符（如纯电话销售、外包驻场运维、要求 5 年以上资深管理经验）或黑名单公司的岗位，避免无效沟通。
3. **分画像定制首聊话术与简历映射**：命中不同画像的岗位自动绑定对应方向的定制招呼语与作品集深链（如指向 `myzjx.com` 上的具体软件作品页或 B 端产品复盘文章）。

## 二、SQLite 本地幂等账本：每一次触达皆可追溯

为了防止在多轮运行或筛选条件重叠时对同一家公司的同一岗位重复操作，`BossHunter` 在本地维护了轻量的状态存储与幂等检查层：

- **复合唯一键去重**：以平台岗位唯一 ID（或 `公司名 + 岗位名 + 城市` 归一化指纹）作为幂等键，已处理、已跳过或已沟通的岗位在后续轮次中毫秒级短路跳过。
- **全状态审计记录**：每一条扫描过的岗位都会记录匹配得分、命中/拒绝原因、使用的画像标签及时间戳，方便事后复盘哪类关键词组合的回复率最高。

## 三、反自动化节流与安全合规熔断（Safety Circuit Breaker）

在浏览器自动化层（基于 Playwright 构建），`BossHunter` 严格遵守平台合规与安全红线：

- **带抖动的拟人节流（Jittered Throttling）**：在列表翻页、点开详情与发送招呼之间引入泊松分布级别的随机等待时间与每日/每小时配额上限，保持正常的阅读节奏。
- **遇到验证码或风控立即熔断停机**：系统内置了严格的风控检测器——一旦页面出现安全验证弹窗、图形验证码（CAPTCHA）或异常重定向，Agent **绝不尝试破解或绕过**，而是立即保存当前账本状态、暂停自动化循环并通知用户人工接管。

这种“把规则判断与账本记忆交给代码，把安全边界与最终沟通留给人”的混合架构，使 `BossHunter` 成为了一个真正安全、可控的个人求职生产力工具。
