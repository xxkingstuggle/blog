平时在终端里同时跑 Codex CLI、Claude Code 和桌面客户端写代码，如果让每个工具各自直连单一上游接口，用起来非常别扭：

- **客户端带的参数上游不认**：比如 Codex 请求里默认带 `reasoning_effort`（有时还会传 `xhigh` 或 `max`），有些兼容层一收到不认识的字段不仅不报 `400`，直接崩个 `HTTP 500` 回来；
- **账号和线路分散**：手头既有按量计费的 API Key，又有要走 OAuth 动态刷新的订阅号（比如 Google AI / Claude / WorkBuddy），散在各个工具的配置文件里，哪个限流了都得手动去切；
- **网关一挂全停工**：本地网关容器要是更新配置或升级镜像时崩了，手上正在跑的几个编码窗口会同时断连。

为了把所有渠道收口到一个稳定的本地入口，我把 **New API**、**Sub2API** 和 **CLIProxyAPI (CPA)** 都搭起来试了一遍，最后定下了现在的本地架构。

## 为什么最后选了 CLIProxyAPI + Magpie 做主力？

这三个开源网关我都跑过，侧重点差别很明显：

| 工具 | 适合干什么 | 我实际用下来的痛点或优势 |
|---|---|---|---|
| **New API** | 多人共用分发 Key、统计额度、配标准 OpenAI 渠道权重 | 后台面板很全，但遇到需要深度改写请求体或自己维护复杂 OAuth 握手的私有渠道，得去改核心代码 |
| **Sub2API** | 把网页或客户端订阅账号快速转成标准接口 | 足够轻，但路由编排和自定义扩展能力比较简单 |
| **CLIProxyAPI (CPA)** | 给本地 CLI / IDE 编码工具做协议转换与 OAuth 托管 | 支持挂载 Go `c-shared` 动态库插件，能把私有渠道（如 WorkBuddy、QoderWork）拆成独立插件维护，不污染主程序 |

所以我现在的分工是：在 OrbStack 容器里跑 **CLIProxyAPI (`cpa-local`)** 负责底层的 OAuth 续期、插件加载和协议清洗；外层用本机的 **Magpie** 管路由组顺位和客户端可见性，哪条主线路 429 限流了自动切到同组候补线路。

## 踩坑实录：修掉 OpenCode Zen 渠道的 `reasoning_effort` 500 报错

接第三方渠道时，最烦的不是连不上，而是平时聊天好好的，一用 Codex 跑长任务就偶发报 `HTTP 500`。

抓包看请求体才发现两个问题：

1. **参数不兼容导致上游直接崩 500**：Codex 请求里带的 `reasoning_effort` 值超出了某些上游模型支持的范围，上游服务端没做参数校验直接抛了 500。
2. **客户端对着必败的 500 死磕重试**：客户端看到 500 以为是服务端临时抽风，默认还在原地做指数退避重试，白白卡住半分钟不切备线。

针对这个问题，我在适配层做了三处改动：

- **转发前先洗一遍参数**：按目标模型实际支持的枚举表，在转发前自动把不支持的 `reasoning_effort` 裁剪掉或映射成合法档位（如 `high`）。
- **单渠道代理隔离**：给需要走特定代理的渠道单独配独立的 `http.Transport`，不读全局 `HTTP_PROXY` 环境变量，省得一个渠道改代理把直连渠道也带沟里去。
- **区分“真抽风”和“参数/鉴权硬错误”**：只有遇到 `429`、`502`、`503` 或连接重置才重试；遇到 `400`、`401`、`403` 或带特定错误签名的 `500`，立刻放弃当前节点，直接切同组下一条线路。

## 每天早上的网关自动巡检与失败回滚

因为上游 `CLIProxyAPI` 和我自己的插件都在频繁更新，如果直接在正在跑的容器上拉代码重编译，哪天上游引入了破坏性改动，我一早打开电脑就没法干活了。

所以我配了一个每天早上 `09:00` 定时跑的维护脚本，按四个步骤走：

1. **先看有没有新提交**：拉取上游源码和插件状态，对比当前容器的 Commit SHA；如果没变化且健康检查正常，直接静默退出。
2. **在隔离目录编译**：有更新时，先在临时构建目录里把主程序和 `.so` 插件编译出来，绝不直接覆盖正在跑的二进制文件。
3. **发真实请求验活**：用新构建的镜像起一个候选容器，先后测 `/v1/models` 枚举和一次最小的流式对话请求，确认插件加载、Token 续期和流式返回都没问题。
4. **通过才切流，失败自动回退**：只有探针全绿才替换现役容器，同时保留上一版好用的镜像标签（比如 `cpa-local:8.1.1`）并清理多余的悬空旧镜像；哪一步报错了就立刻回滚到上一版镜像，把报错日志写进文件提醒我处理。
