市面上的习惯打卡应用大多走向了两个极端：要么做成带社区、排行榜和账号体系的重型产品，要么是功能单薄到用两天就腻的清单。我用过的几款都在同一个地方劝退我——打开应用本身这件事，比我今天要打卡的那个习惯还要费劲。

我想做的东西非常收敛：**让「今天该做的事」在手机桌面上就长得像一个你愿意伸手去点的东西，点完即走。**

## 1. 我定义的边界

一个产品最容易失控的地方，是功能清单。我在动手之前先写下了四条不可协商的约束，后面所有取舍都拿它来判断：

- **快**：冷启动到能看到今天的卡片，不能有加载态。
- **本地优先**：不登录也能完整使用，网络只是可选项。
- **最小签名面**：用免费 Apple 账号也能侧载到真机，不引入任何需要付费开发者账号的能力。
- **隐私边界清晰**：云端只同步文字字段，自定义图片永远不上传。

这几条约束直接砍掉了一大批「看起来很合理」的功能：iCloud/CloudKit 同步、推送式服务端提醒、Live Activities、灵动岛提醒，全部不做。它们要么需要付费账号，要么让签名的复杂度超出个人项目的承受范围。

最终落地的范围是：自定义习惯（名称、图标、颜色、卡片样式、目标周几、提醒、排序）、贴纸式首页卡片、内置 emoji 与 SF Symbols 的图标选择器、打卡音效与动画、本地通知、以及三类 WidgetKit 桌面小组件。数据层用 SwiftData，Mac Catalyst 版本可以直接在 Mac 上跑同一套逻辑调试。

## 2. 最难的一个问题：免费签名下小组件拿不到数据

这是整个项目里唯一让我真正卡住的地方。

常规做法是主 App 与小组件通过 App Group 共享数据。这在模拟器里和 Xcode 有线调试时完全正常，但当我把应用侧载到真机之后，小组件就开始随机显示空白或过期数据——**第三方重签名会破坏 App Group 的共享关系**。这是个不在 Apple 官方文档里、但每个做过个人侧载的人都会撞上的坑。

我的解决办法换了一条路：既然本地共享不可靠，就绕开它。

- 主 App 在关键时机把一份**渲染好的快照**推到 Cloudflare Workers + Durable Objects。
- 小组件只做一件事：用共享的 `HABITBLOOM_REMOTE_DEVICE_KEY` 去读这份快照并直接渲染。
- App Group 降级为 Xcode 环境下的本地兜底，不再承担真机路径。

这样小组件拿到的永远是「已经算好的结果」，而不是需要它自己去 SwiftData 里重新查询和聚合。顺带解决了一个性能问题：统计聚合不再在小组件的紧张时间预算里执行。

同一条思路也用在云端备份上：**只同步文字**。习惯的名称、配色、周期、打卡记录这些字段体积极小，几分钟就能同步完；而用户为大卡片挑的那张照片，裁剪压缩后就只存在本地。

这里还有一层诚实的取舍要说明。整个云端路径**没有被设计成多端冲突解决的完整方案**——没有冲突合并 UI，也没有离线队列重放。它解决的是一个具体问题：「侧载环境下怎么让桌面小组件可靠地显示内容」。把它包装成「全平台实时同步」是不诚实的，我没有那样做。

## 3. 我怎么和 AI Agent 协作

一个人写完整应用最危险的地方不是写不完，而是**没有人在架构层面反驳你**。我用 AI Agent 来补这个位置，但我从不把它当代写工具。

我的用法是把它放在**审查者**的位置上，而不是执行者的位置上：

**需求先行，代码后写。** 我不会说「帮我写个打卡 App」。我会先把上面那四条约束、数据模型、签名限制写成一份明确的规格，再让它实现其中一个已经边界清晰的部分——比如「给定一个 SwiftData 模型，自动生成 `[year][month]` 维度的热图聚合，且不得在主线程做全量历史扫描」。约束越硬，产出越可用。

**让它做我做不到的事：穷举。** 这个项目里有一份 `PERMISSIONS.md`，逐项列出 App Groups、CloudKit、Push、Live Activities 等能力的使用状态，及每一项对免费签名的风险。这类「把所有可能踩到的坑一次列全」的工作，是我自己最容易遗漏、而 Agent 特别擅长的。我用它来做交叉检查，而不是让它凭空想象——所有结论我都会回到 Apple 文档和真机构建上去验证。

**不信任自述，只信任 Diff 与构建。** Agent 说「已完成」从来不算完成。我要求每个改动落成可被 Git 审查的差异，并跑通 `xcodebuild` 与项目里的 smoke/stress 测试。项目里有一份 Buildoles 环境的踩坑记录就来自这里：某个 iOS Runtime 缺失导致 `actool` 报错、打包直接失败——这类问题只有在真实执行构建命令时才会暴露，读代码是读不出来的。

这也带来一个我需要诚实承认的局限：**AI 生成的代码在 SwiftUI 这类框架的版本差异上并不可靠**。它给过的某些 WidgetKit 写法在当前 SDK 下已经变更，最终正确版本是靠编译器的报错一条条修正出来的。所以我把它的产出当作「高质量的起点」而非终点。

## 4. 成品与代码

HabitBloom 目前的状态是一个**可用的个人产品**，而不是一个演示 Demo：

- iPhone / iPad / Mac 三端运行同一套代码
- 三类桌面小组件，真机侧载下可靠刷新
- 统计、连续天数、月度热力图
- 可选 Cloudflare 轻量备份
- Core smoke 与 stress 测试可执行文件

明确**没有做**的部分我也同样记录在项目里：CloudKit 同步、服务端推送提醒、完整的图片裁剪 UI、小组件直接打卡按钮、以及 IPA 打包分发流程。这些不是疏忽，是我在当前约束下主动选择的留白。
