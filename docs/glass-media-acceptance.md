# 专项验收：圆角媒体与内容取色玻璃（2026-11-13）

## 要达到的体验

用 MYZJX 自己的产品截图、文章封面和私人应用预览，呈现**图片染色到周围玻璃层**的柔和通透效果；保持 Godly 式内容优先的结构。参考 Apple Liquid Glass 的环境适应与层次，以及小米 HyperOS「柔光玻璃」的环境色融合，而不是复刻厂商专有的光学渲染器。

- 参考：[Apple 官方设计介绍](https://www.apple.com/newsroom/2025/06/apple-introduces-a-delightful-and-elegant-new-software-design/)；[小米 HyperOS](https://hyperos.mi.com/)。
- 适用页面：公开首页和作品列表、文章图片详情、软件详情产品截图、私人应用中心。导航与移动端仅需要轻量半透明背景；避免大面积模糊遮蔽文字。
- 不修改登录鉴权、D1/Worker、博客数据及下载链接，不更改 main。

## 任务清单与不可妥协的验收条件

- [x] 归纳真实页面的层级、视觉边界，确定**媒体实际像素边界**也必须圆角。
- [ ] **G1：圆角三层吻合。** 卡片壳、内层媒体背景、实际 \`img\` 均有可计算的正圆角；真实图片本身不允许显示直角边。内层不溢出父层圆角，阴影不会穿透裁切边界。
- [ ] **G2：真取色。** 从同源图片实际像素（缩小采样）提取主色和辅助色，不为所有卡片套相同蓝色；无彩色/读取失败时退回柔和中性色。
- [ ] **G3：可见但克制的玻璃。** 画面附近有低透明度的主辅色径向光晕、细微边缘高光、半透玻璃层；图片本身颜色和可读信息不被覆盖，不加夸张扫光、旋转、鼠标追踪。
- [ ] **G4：不同素材。** 横向、竖向、接近正方形媒体和无图长中文内容保持自然宽高比。仅有实际图片时才做像素取色。
- [ ] **G5：详情页。** 文章封面与软件详情截图都使用同一材质语言和独立圆角；无封面的文章不补虚假的大图。
- [ ] **G6：私人应用。** 三款应用预览用各自的调性色彩、柔光与边缘玻璃层，绝不伪造当前进度或统计数。
- [ ] **G7：系统深浅色。** 亮、暗模式不出现脏白雾、文本低对比、光晕变霓虹；CSS 变量同一套来源。
- [ ] **G8：Safari & 性能。** 320/390/768/1440px 不横向溢出；无请求外部图片取色服务；每张图仅缩小取样一次，延迟加载可处理；动画低动态偏好回退。
- [ ] **G9：浏览器断言。** WebKit 自动检查实际 \`img\` 与媒体层圆角、颜色变量已从真实图像得到、前两张图片色彩有区别、相关产品及详情仍能点击、触摸与深色模式正常。
- [ ] **G10：视觉复核。** 对比 WebKit 桌面与移动端截图，排除难看的矩形白块、异常遮罩、截断和图片超框。将截图作为 PR CI 构建产物。

## 具体实现路径

- \`src/scripts/glass-palette.ts\`：不引入第三方依赖的浏览器本地像素采样，优先采有色区域；缓存本次页面相同图片的结果，\`load\` 时惰性执行，忽略第三方/跨域不可读图片，绝不上传像素。
- \`src/styles/glass-media.css\`：图像/框体统一圆角、内容色渐变、内表面高光；放在现有样式最后，避免前面历史样式覆盖。设备不支持模糊属性时依然有纯 CSS 的清晰效果。
- \`src/styles/admin-glass.css\`：私人应用的轻柔同类材质，来源是自身界面的主调色而非欺骗性取图。
- \`scripts/verify-studio-webkit.mjs\`：WebKit 计算属性与页面流程验证，必要时追加截图。
- \`.github/workflows/verify-iteration-webkit.yml\`：新文件变化触发回归测试。

## 风险与边界

CSS 的模糊、色彩融合是网页对玻璃视觉语言的近似，不等于苹果系统私有光学折射。透明度不应靠无限增大 \`backdrop-filter\` 获取。取色失败或用户禁用 JS 时，图片圆角、基础柔和背景和业务导航必须照常工作。自动浏览器验证不等于真实 iPhone 的主观视觉验收；在真实设备测试前不得合并发布。
